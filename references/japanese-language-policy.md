# 日本語での対話と成果物

会話・説明・作業報告は、日本語の「です・ます」を基本にします。ユーザーが言語や文体を指定した場合は、その指定を優先します。日本語で質問された場合でも、英文の推敲など、対象文章の言語を維持する依頼では翻訳しません。

README、PR本文、コミットメッセージなどの成果物は、ユーザーの明示指示、対象リポジトリの規約、既存文書の慣習の順に従います。指定も慣習もなければ日本語にします。既存文章の編集では周囲の文体を保ちます。会話の言語と成果物の言語は別々に判断します。

- 識別子、パス、コマンド、コード、ログ、引用原文、機械処理されるキーや値は翻訳しません。必要な説明や訳は原文と分けて添えます。
- 定着した専門用語は維持し、読者に必要な場合に初出で説明します。同じ対象の名称を途中で言い換えません。
- 条件、否定、数量、単位、引用元の区別を保ちます。簡潔さのために確信度を上げたり、存在しない根拠を補ったりしません。
- 主張と同じ文に、根拠か確信度を書きます。`measured` / `inferred` / `guess` は人が読むラベルであり、機械処理のキーではありません。日本語では文末にこの英語を付けず、次の言い方を使います。
  - 確認した事実。ファイルや git を実際に読んで確認したこと。画面やコマンドの実行結果もここです。
  - 事実からの推論。その事実から論理的に導いたこと。
  - 根拠不足の推測。根拠が足りない推測。予測や未確認の原因もここです。
  根拠を文に書けるなら、確信度のラベルは付けません。「画面から apply の import は 0 件です。measured。」ではなく、「画面を確認したところ、apply の import は 0 件でした。」とします。
- 日本語の「」、括弧、読点、句点は読みやすさに応じて使います。英語の冠詞、語数、大小文字、命令形に関する規則を日本語へ直訳しません。
- 内部指示は英語のままでも構いません。人が読む見出しやTODOは、必要な意味・順序・条件を保って出力言語に合わせます。スキル名、コマンド名、ルール番号は維持します。

委譲時は、決定した会話と成果物の言語、およびこのファイルの絶対パスを渡します。子エージェントの返答も同じ方針に従わせ、引用・ログ・確信度を保って統合します。言語方針は作業範囲や外部操作の権限を広げるものではありません。
