# 日本語の推敲

以下は置換辞書ではなく、読みにくさを見つけるための例です。意味や口調が変わる場合は置換しません。原文の意味が曖昧なら、推敲だけで解釈を確定せず、必要な確認点を示します。

| 確認する表現 | 改善例・判断基準 |
| --- | --- |
| 「設定を変更することができます」 | 意味が同じなら「設定を変更できます」。可能であるという意味は残します。 |
| 「確認を行う」「保存されるという形になります」 | 「確認する」「保存されます」。実際の動作や状態を述べます。 |
| 「結論から申し上げますと」「重要なポイントとして」 | 前置きに情報がなければ削り、内容から始めます。 |
| 「包括的」「シームレス」「堅牢」「大幅に改善」 | 対応範囲、操作、保証、実測値が示せるなら具体化します。根拠がなければ保証や数値を創作しません。 |
| 「〜と考えられる可能性があります」 | 推測の強さを変えず、重複だけを削ります。「可能性があります」を断定に変えません。 |
| 「ソリューションをレバレッジする」 | 実際に使う対象と動作を書きます。「キャッシュ」「API」など定着した語は無理に和訳しません。 |
| 「素晴らしい質問です」「お役に立てれば幸いです」 | 求められた社交的な文章でなければ、定型の称賛や結びを削ります。 |
| 短い文・体言止めの連続 | 条件、理由、結果のつながりを戻します。短さだけを目標にしません。 |

「必要です」「必須ではありません」「最大3回」「3回以上」「未確認です」は意味を担います。削除・反転・丸めをしません。曖昧な「これ」「対応する」は、対象が確定できる場合だけ具体名にします。

例:

> 結論から申し上げますと、キャッシュの活用を行うことで応答時間を大幅に改善できる可能性があります。ただし、現時点では計測を行っていません。

→ キャッシュで応答時間が短くなる可能性があります。効果はまだ計測していません。

推敲後に、事実・条件・否定・数値・出典・不確実性が残っているか確認します。引用やコードの中にある同じ表現は変更しません。
